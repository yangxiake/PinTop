# 0.1.7 原生 macOS UI 回归记录

环境：2026-10-04，macOS 27.0.1、Apple Silicon、Xcode 27.0；本机开发构建 `build/PinTop.app`。

| 项目 | 结果 |
| --- | --- |
| 工程与构建 | 原有界面为 AppKit。Debug、Release `xcodebuild` 均通过；当前 Debug `.app` 的 `codesign --verify --deep --strict` 通过。 |
| 主窗口 | 原生 Toolbar、`NSTableView`，权限为轻量状态；窗口标题、应用图标、图钉按钮与计数按预期显示。默认窗口宽 520pt，按首批窗口数缩放高度，可手动缩放；最大化后列表仍可滚动，已恢复紧凑尺寸。 |
| 列表状态 | 独立 UI 预览分别以 0 行与 10 行运行。0 行显示“尚未添加窗口”和“添加窗口…”；10 行显示滚动条，已置顶行的 `pin.fill`、浅色背景和计数正确，图钉与滚动条没有重叠。预览进程已结束。 |
| 外观 | 本机深色与浅色模式分别检查主窗口和设置窗口；用户原来的深色模式已恢复。 |
| 设置 | 原生 `NSSwitch` 显示三个保留的选项；单独窗口标题为“设置”，左上角关闭、`⌘W` 可关闭，主窗口仍可用。 |
| 权限与图标 | 未授权时显示“需要辅助功能权限”和“授权…”；刷新本地构建授权后显示“辅助功能权限已开启”，读取真实标题。系统“设备控制和数据访问”列表中 PinTop 显示自有图标。 |
| 置顶与取消 | 临时 AppKit 窗口在主列表点击图钉后出现目标窗口上的“取消置顶”角标；重新打开主窗口可见 1 个已置顶及填充图钉；直接点列表图钉取消后计数归零。另一次通过目标角标取消也成功。临时测试窗口已停止。 |
| 快捷键 | `⌘N` 打开新的选择提示并收起主窗口，提示中的“取消选择”可退出；`⌘R` 对新建和已关闭的临时窗口分别更新列表；`⌘,` 打开设置；`⌘W` 关闭设置；`⌘Q` 退出应用，重新启动后授权仍有效。 |

实体键盘 Esc 仍未单独复核。图形自动化发出的 Esc 未进入全局事件捕获，不能据此判定实体按键行为。一次对系统设置窗口快速再次置顶返回“恢复进程未就绪”，安全回滚后无已钉窗口；稳定的临时 AppKit 窗口置顶与取消均通过。登录时打开未通过重新登录实测，多显示器及多桌面未在本轮 UI 回归中复测。

代码审查：移除了旧主面板的自绘行/按钮布局、设置页的返回与退出按钮、未读取的 `AXTrustedAtLaunch` 偏好、无调用的 `SettingsPanelController.hide()`、`PinTopButton` 中仅供旧面板使用的 primary/secondary 样式分支。`PinTopButton` 仍由跨应用的窗口角标使用；窗口扫描、Space 管理、恢复 helper、置顶角标和针模式模块均仍有实际调用。Debug 专用的诊断命令保留在条件编译中，不进入 Release。
