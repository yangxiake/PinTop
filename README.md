# PinTop · macOS 窗口图钉

PinTop 是一个 Swift/AppKit 菜单栏应用，尝试把其他应用的**原窗口**留在普通窗口上方。它不要求关闭 SIP，不截屏、不镜像窗口，也不向目标进程注入代码。当前开发与实测环境是 **macOS 27.0/27.0.1、Apple Silicon、Xcode 27.0**；其他系统和 Intel 尚未验收。

0.1.3 版使用系统 SF Symbols 和应用原生图标绘制控制窗口，增加统一的应用图标。窗口右上角的“已置顶 · 取消”角标采用系统材质，并以每秒 60 次的几何检查跟随窗口移动；没有已钉窗口时自动停止检查。2026-10-03 的临时 AppKit 窗口与当前 PinTop 界面测试确认：拖动后角标仍位于窗口右上角，点击角标可直接取消。

0.1.7 版用原生 AppKit Toolbar 和 `NSTableView` 重构控制窗口：工具栏提供“添加窗口…”、刷新、更多与设置；列表用图钉图标切换置顶，权限状态以轻量文字显示。设置位于独立窗口，关闭即可返回主窗口；PinTop 应用菜单提供 `⌘,` 设置和 `⌘Q` 退出。主窗口支持缩放、空状态、浅色与深色模式。应用图标同时加入 Asset Catalog，辅助功能授权列表已在本机显示图标。本机检查见 [`Tests/acceptance-2026-10-04-native-ui.md`](Tests/acceptance-2026-10-04-native-ui.md)。

## 直接在 Xcode 中开发

打开 [`PinTop.xcodeproj`](PinTop.xcodeproj)，选择共享的 `PinTop` scheme，目标选“我的 Mac”，按 `⌘R` 构建运行。工程已经包含全部 Swift 源码、Info.plist、菜单栏应用设置和 ad-hoc 签名配置，无需导入现有文件或安装 XcodeGen。

命令行复现 Xcode“运行”使用的 Debug 构建：

```sh
./scripts/build_app.sh
```

Xcode“运行”和上述脚本都输出到同一个 [`build/PinTop.app`](build/PinTop.app)。这是本地开发版本，并非已公证的发布包；登录启动由应用内开关控制。

## 使用

1. 每次启动都会打开 PinTop 控制窗口，默认也能在程序坞找到它。列表显示当前桌面的普通窗口；点击某行右侧图钉后控制窗口收起，目标应用保持活动。目标窗口标题区域出现“取消置顶”角标，直接点击即可取消。关闭控制窗口后应用继续运行；点程序坞图标或菜单栏的 PinTop 可再次打开。退出请使用 PinTop 菜单的“退出 PinTop”或 `⌘Q`。
2. 在工具栏点击“添加窗口…”或按 `⌘N` 进入桌面选择模式。屏幕上方显示提示和“取消选择”按钮；移动鼠标到目标普通窗口会出现边框高亮，单击确认后直接返回目标窗口。按 `Esc` 或点击“取消选择”可退出选择。`⌘R` 刷新列表，`⌘,` 打开设置。右键或按住 Option 单击菜单栏 PinTop 可打开管理菜单。
3. macOS 27.0 的辅助功能授权页面显示为“隐私与安全 → 设备控制和数据访问”；应授权 `build/PinTop.app`。重新构建会改变本地 ad-hoc 签名；如页面仍显示已开启、应用却报告未授权，可先执行 `tccutil reset Accessibility local.pintop.app`，再为当前构建开启授权。

同一用户会话只允许一份 PinTop 主应用运行。Xcode“运行”与构建脚本共用一个应用包；如果已有实例，再次启动会提示打开当前实例的控制窗口，以免出现两个图钉和相互冲突的状态。公开仓库的本机构建产物不要与开发构建同时保留在可检索位置。

确认选择点击会被 PinTop 消费；选中后按用户意图激活目标应用。窗口由原应用继续绘制并处理输入。默认开启的取消角标会加入对应窗口的置顶空间，并核实它位于原窗口上方；角标无法正确显示时会取消这次置顶，避免留下没有窗口内取消入口的状态。菜单列表与角标来自真实的成员关系读回，不把发出请求直接当作成功。

**已知限制：已钉窗口可能遮挡其他应用的菜单或输入法候选窗。** 遇到时可点目标窗口上的“取消置顶”。本版未启用归档研究中的实验性菜单裁剪。针模式已由实体鼠标验证高亮、图钉提示和单击选择；Esc、普通双桌面及多显示器 UI 仍需回归。

## 当前验证

在上述本机配置下，Xcode Debug/Release 构建通过；三个临时 AppKit 测试窗口验证了原窗口排序、另一个应用保持活动、单项取消不影响其余项、正常取消恢复；另测了同应用双窗口与最小化后恢复。主进程 `SIGKILL` 时独立 helper 恢复成功；主进程与 helper 同时结束后，下次启动恢复成功。详细步骤与未测项见 [`Tests/acceptance-2026-09-30.md`](Tests/acceptance-2026-09-30.md)。研究档案未包含在公开仓库。
